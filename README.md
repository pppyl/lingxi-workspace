# 本地工具台 · 统一 APP 登录

Python + Flask 本地网页，默认地址 http://127.0.0.1:5500/ 。

## Windows 客户端下载

直接从 [GitHub Releases](https://github.com/pppyl/lingxi-workspace/releases/latest) 下载 Windows x64 单文件版 EXE，双击运行，可直接转发给其他人。无需安装 Python 或 Node.js，界面在系统默认浏览器中打开；v1.0.1 起不再捆绑 Chrome。周三活动设备组件使用已安装的 Chrome 或 Edge，不读取日常浏览器登录数据。也提供 ZIP 文件夹版，完整解压后双击其中的 `LingxiWorkspace.exe`，并保留旁边的 `_internal` 文件夹。

关闭标签页后客户端留在托盘继续执行定时任务，再次运行时复用已打开的页面，右键托盘图标可退出。启动时确认本地页面可访问后才打开浏览器；客户端 Cookie 名称与源码网页服务分离。账号及任务保存在 `%LOCALAPPDATA%\LingxiWorkspace`，与程序文件分离，升级无需搬运账号库。更新前先退出旧版本，首次使用登录自己的手机号。详细说明见 [DESKTOP.md](DESKTOP.md)。

从源代码构建：Windows x64 安装 Python 3.12 与 Node.js，执行 `pip install -r requirements-desktop.txt`、`npm ci --prefix recharge`，再运行 `python build_tools/build_windows.py`。构建脚本只收集列出的资源，不包含 `.local`、开发账号库或测试数据。产物位于 `release/`，外部运行时版本及校验和记录于 `build_tools/runtime-lock.json`。

## Android 独立版下载

在 [GitHub Releases](https://github.com/pppyl/lingxi-workspace/releases/latest) 下载 `LingxiWorkspace-1.2.0-Android-arm64.apk`，适用于 Android 7.0+ ARM64 手机。服务、账号和任务在手机本机运行，不需要连接电脑；更新时使用同一签名覆盖安装，保留本机数据。后台任务受系统电池策略影响，详细说明与构建方式见 [ANDROID.md](ANDROID.md)。

## 页面与使用

所有页面共用深色侧栏、蓝色操作按钮、浅灰背景与白色卡片。导航按功能分组：灵犀对话下有“即时对话、定时发送”，周三充值日下有“活动与奖品、领取任务”；分组可展开或收起，顶部路径同步显示父级。账号管理作为公共入口，在当前页弹窗打开。首页展示真实账号数量、需验证账号、待执行的两类任务及最近回复；窄屏使用可展开的侧栏，任务表保持整页纵向滚动。

- 功能首页：http://127.0.0.1:5500/
- 账号管理：各页面点击按钮后在当前页面弹窗打开；也可直接访问 http://127.0.0.1:5500/accounts
- 灵犀多账号对话：http://127.0.0.1:5500/lingxi
- 周三充值日：http://127.0.0.1:5500/recharge/
- 签到有礼：http://127.0.0.1:5500/checkin
- 每月话费券：http://127.0.0.1:5500/monthly-coupon
- 我的卡券：http://127.0.0.1:5500/coupons
- 定时任务管理：http://127.0.0.1:5500/recharge/static/tasks.html （首页和活动页均有入口）

1. 运行 `python -m pip install -r requirements.txt`，然后运行 `start.ps1`。
2. 点击「账号管理」会在当前页面打开弹窗，负责手机号、验证码登录，以及账号备注、校验和退出。点击右上角关闭、按 Esc 或点击遮罩即可返回原页面；再次打开保留未提交的输入。
3. 一个手机号只保留一份 APP 登录态。已有登录和正在接收验证码的流程都会复用，不重复登录。多个手机号可分别加入共享账号池。
4. 灵犀、周三充值日、签到有礼、每月话费券和我的卡券使用同一个账号池，各功能分别选择账号。
5. 灵犀切换账号时保留当前页面中的各账号对话，并为每个账号维持独立的会话 ID。不同标签页也可以指定不同账号。聊天文本不写入磁盘，刷新页面会清空显示。
6. 活动页只保留账号选择、本场资格、奖品和下一次预约摘要。选择尚未连接的账号时点击「使用所选账号」，已连接的账号可直接切换和查询。点击「任务管理」新建多账号预约；活动页的「调整预约」直接打开对应任务的编辑窗口。重复选择同一手机号不会创建重复活动账号。
7. 退出账号统一在账号管理弹窗完成，只清除该手机号在各功能中的会话和相关等待任务，其他账号保留。正在接收回复或执行任务的账号需先结束操作。

## 我的卡券

侧栏一级入口“我的卡券”复用共享 APP 登录，直接切换账号查看可用券和卡券历史，无需连接手机或再次登录。支持名称搜索、话费券/流量券/其他类型筛选、综合排序、最近领取、最早领取及即将失效排序；历史按官方已使用、失效及两类数据源读取并分页展示。表格显示券名、来源、面额、有效期和真实状态，详情提供官方使用说明。接口没有确认的领取时间不作推算。

查询经 APP 短期令牌建立独立卡券会话，并校验返回手机号与所选账号一致。账号卡片显示当前可用券数量，进入页面分批查询；待生效或已锁定的券不计入，失败显示未获取。正常维护只更新版本信息时不打断用券；等待用券验证码期间暂缓该账号续期。卡券兑换号码及认证令牌不返回前端，也不持久化。

已支持普通话费兑换券（如 2 元兑换券）和固定话费加赠券（如充 30 元赠 6 元）：在对应卡券上点击“兑换话费”或“充值使用”，先核对官方规则。兑换券按官方要求获取短信验证码，再点击确认提交；加赠券自动选择优惠比例最高的充值档位，比例相同选择实付更低的金额，展示唯一的最优方案及到账金额，确认后生成待支付订单。订单生成后直接读取官方支付宝网页收银台链接与二维码，支持打开网页和复制链接，付款由用户手动完成。点击已提交卡券会继续原订单；客户端支付宝唤起逻辑已移除。订单已创建不表示已付款，兑换受理也不等同话费到账。刷新后可在“待支付订单”继续；已取得的网页支付链接随原订单加密保存，刷新链接失败时保留原入口。链接有效期由官方收银台控制，过期时可点击“刷新支付链接”核实；官方明确关闭的订单会停止续付。官方返回支付宝 SDK 参数时，会继续向官方接口换取支付宝 HTTPS 网页链接，不生成客户端唤起地址；旧版保存的银联中间收银台地址会重新获取。遇到官方滑块时由用户完成，成功后自动继续下单或获取付款链接，付款仍由用户手动确认。满减券按官方门槛生成最优充值方案；锁定／占用的券需查看原订单。

使用前核对卡券和共享凭据；已失效或待生效的券不显示使用入口。操作有效期十分钟，短信和券码只保留于内存。提交前将去重标记加密写入 `coupon_use_data`，保留订单号与结果；提交超时或程序中断时显示待核实，不重复用券。已受理后自动关窗、刷新卡券并显示约三秒的成功提示。官方滑块由用户完成，成功后自动继续，失败时获取新验证。充值需要重新登录时，当前弹窗自动发送一次登录验证码；登录后重新读取券，仍需确认才会下单。100MB 流量日包权益券按官方详情要求进行短信认证，再提交流量兑换申请；有额外协议或尚未适配的券型提示前往 APP 处理。

## 签到有礼

侧栏入口位于“周三充值日”下方，与其他功能共用 APP 登录，无需连接手机。默认表格按共享账号逐行展示今日签到、当月累计、最近执行结果、自动签到与月末秒杀状态。支持状态筛选、账号搜索、单号签到、批量配置、执行记录及批量停止。未查询的累计次数显示“—”，不填造 0 或成功状态。

选择账号后可开启每天签到，默认北京时间 08:00，可修改。程序启动时检查已开启的账号：已过设定时间且今天未签到就补签；已经签到则跳过。时间尚未到只查询状态。所有写请求先读取官方时间和日历记录，提交标记与结果加密保存在 SQLite 的 `checkin_data`，防止重启或重复点击重发；提交后结果不明时只查询核实，不盲重发。

月末秒杀每天北京时间 11:59:30 开始认证并预热各账号的独立活动连接，按官方服务器时间等待 12:00，再按间隔并发尝试免费 2 元话费券。默认每账号 40 次、间隔 0.05 秒、8 个并发线程；三项均可在“配置自动任务”或任务“调整”中修改。页面顶部“秒杀设置”可将单账号默认并发改为 1–32，并同步到已有任务，正在执行的本轮不变。各账号独立使用并发额度，超过单账号并发数的请求排队；如果主轮次仍只有繁忙或尚未开始的回复，在最后一次计划请求的 10 秒后补试一次。退出账号会删除对应签到、秒杀任务、历史及缓存；启动时清理旧版残留。

当日须已签到、有库存且未达到领取上限。每次重新取当日场次和奖品 ID，不复用前一天的值；未开放或已领时记为跳过。成功、抢完、达到上限、凭据变更或官方要求验证后取消未发送请求，已经发出的请求保留结果；网络中断导致结果不明时只查询核实。每轮提交标记与每次请求结果加密持久化，已提交的轮次重启后不重放，预热中断且尚未发送的本场任务可继续。任务“记录”中可展开查看每次实际发起的毫秒时间与回复。错过 12 点超过两分钟不会补抢。签到与领券都使用共享池最新 APP 凭据建立活动 SSO，会话中凭据变化时中止本次提交。

自动任务需要本地服务持续运行，电脑开机、联网且不休眠；关闭浏览器页面不影响客户端托盘中的服务。当前版本已实测 APP SSO、官方日历查询、真实签到及启动补签；12 点领券尚未在线上执行，结果以官方回复为准。

## 每月话费券（贵州移动）

对应贵州 APP 首页“先领券再充值”。表格按账号分别显示直接券、三个浏览任务、累计打卡天数、额外券和自动执行状态，支持搜索、筛选、全选与批量设置。

- 玩法一：每个账号每月直接领取一次，按官方实际结果记录券种和使用条件。
- 玩法二：按官方流程完成查询个人账单、浏览签到活动、浏览网龄专区；每天打卡一次，累计三天、官方进度达到 100% 后领取额外券。两个玩法分别按月去重，打卡按天去重。
- 自动检查默认北京时间 08:05，可修改。程序晚于设定时间启动时补做当天检查。每月按官方时间启用新周期，过往已领记录不会被误认为本月结果。
- APP 共享凭据通过 `getBigNetToken` 认证到贵州活动，无需手机、独立短信登录或手工 Cookie。活动会话只在内存中使用，任务设置、提交标记和结果加密保存在本机 SQLite。
- 结果不明时先保留提交标记，避免重启后重复发送；官方明确要求活动协议或额外验证时，提示在 APP 完成，不自动代签。历史奖品缺少月份时显示待核实，只在本月成功响应或官方明确已领取后确认。

定时执行需要本地服务运行、电脑联网且不休眠。日常修改只在本地实现与验证，GitHub 同步和客户端打包由用户明确要求后执行。

灵犀账号列表直接铺在对话左侧，支持搜索，显示备注、脱敏号码、登录状态和最近校验时间；需要处理的账号另显示失败原因。正常账号优先显示，已标记失效的账号禁止选中，可直接点击「重新登录」进入原手机号的验证码流程。页面每 15 秒同步一次，也可手动刷新状态；当前账号失效时禁用发送，保留已有对话。点击可用账号会自动连接。添加、备注和退出账号统一从全局侧栏的「账号管理」进入。

账号显示“需要短信验证”时，点击该账号的「重新登录」会自动向保存的原手机号发送验证码，右侧只需填写验证码并确认。无需重新输入手机号或备注；成功后更新同一账号的共享凭据，保留账号 ID、备注和两项功能的任务绑定。验证码错误可直接重试，也可在倒计时结束后重新发送；若账号已恢复，则直接复用登录，不再发送短信。

账号管理弹窗添加账号不会替换灵犀的当前账号。各页面通过不含凭据的本机事件同步账号列表。验证码不保存，Cookie 和灵犀凭据不返回浏览器，使用 Windows 当前用户的 DPAPI 加密后存入本机 SQLite 数据库。

## 账号数据库与会话恢复

数据库位置：项目根目录的 `.local/accounts.sqlite3`，无需另装数据库服务。`account_sessions` 保存稳定账号 ID、备注、脱敏号码和加密的 APP Cookie / 灵犀凭据 / APP 参数；`activity_accounts` 保存活动账号与共享账号 ID 的绑定。旧的 `recharge/.local/accounts.json` 账号目录会自动导入，之后写入数据库，原文件保留。定时任务和执行记录仍保存在 `recharge/.local/schedules.json`。

服务启动后读取账号库，每 10 分钟调用 APP 的 `/biz-orange/DN/refreshSession` 维护主会话，临时故障按 60 秒间隔重试。主会话超时时，使用已保存的 `refreshToken` 调用 APP 鉴权续期接口；不发送短信。登录与续期返回的设备参数、XK、refreshToken、有效期和 Cookie 均加密保存。刷新使用版本比较，防止迟到结果覆盖新凭据；Cookie 改变后重新换取灵犀凭据，活动重连从共享账号池读取最新版。活动认证失败单独显示可重试状态，不能据此判定主账号需要短信验证。活动只读恢复最多建立一次 APP SSO 会话，不重放领取请求。

重启保留共享账号 ID、活动账号 ID 和已预约任务，避免重复建号。正常续期在后台完成，业务校验互不阻塞；临时网络或单项业务认证失败不会禁用其他功能，明确需要短信验证时才提示重新登录。已确认失效的状态也会保存，直到用户重新登录。主动退出会移除该账号登录凭据及其签到数据，并停止其他功能的后续任务。

自动恢复需要尚可维护的 APP Cookie 或有效的 refreshToken。旧版未保存 refreshToken 的记录如果已经超时，需要补验证一次；不会反复尝试短信登录。运营商明确撤销凭据、要求安全验证或账号被另一设备重新登录替换时，仍需用户验证。加密凭据仅能由原 Windows 用户在原机器上解密。正常运行不连接手机。

## 周三充值日组件

首次安装活动官方设备标识组件：

```powershell
npm install --prefix recharge
```

需要本机 Node.js 和 Chrome。浏览器只运行官方设备标识脚本，不做第二次手机号登录，不需要 USB 手机。

活动使用 APP Cookie 经过 `/qwhdsso/appTokenLogin` 建立官方活动会话，不能用普通微门户网页登录 Cookie 替代。设备标识来自独立临时 Chrome 上下文，不读取日常浏览器资料。

定时逻辑保留北京时间周三 8 点开放、西藏和新疆 10 点开放、0.2～1 秒随机间隔、每账号最多 20 轮、成功即停和超时先查结果。任务由用户主动设置。账号和绑定保存在数据库，任务及记录保存在 `recharge/.local/`，活动临时 Cookie 和设备标识在恢复时重新建立。

任务管理页集中展示全部已提交账号任务，支持新建多账号预约、状态筛选、账号/手机号搜索、执行时间排序、详情记录、单个或批量停止，以及调整/重新预约。新建时可勾选多个已连接账号；重试间隔、次数及立即执行放在折叠设置内。每周任务显示下次执行时间和上场结果，缺少登录时标记为“需处理”。列表读取本地任务快照，不查询官方资格或触发领取；执行中每秒更新，其他时候每 4 秒更新，关闭页面后任务仍由本地服务执行。

活动页移除了宣传大图、示例券、教程、批量任务表单和日志栏。官方奖池默认折叠，账号入口统一为一条选择栏。静态页面壳可直接更新运行中的页面，无需重启服务或重新登录。

每个账号保留一条任务及最多 45 条执行记录。重新预约会替换该账号原任务并重置计数和记录，保存前有文字说明。任务管理页作为静态页面提供，新增此页面无需重启现有服务，不会清除正在使用的登录态或等待预约。

## 已验证

2026-10-28，使用本人授权的中国移动号码完成了真实短信发送、验证码登录、APP Cookie 获取、灵犀凭据换取、服务端凭据验证和文字回复接收。正常业务路径未调用手机或 ADB。

协议依据用户提供的中国移动 APP 12.5.6，以及手机上 12.0.9 的一次请求比对。AES 请求体、x-token、x-sign、xs 校验均与实际 APP 请求吻合。设备参数由 Python 本地生成。

聊天接口实测收到问候回复「我在，有什么想咨询的，都可以长按对我说~」。其 HTTP/1.1 响应通过 Connection: close 定界且没有长度或分块编码；服务端省略 TLS 关闭通知时，程序按该响应边界结束接收。连接重置、超时、带长度响应的提前断开仍报错，已收到的内容保留。

仅验证了中国移动号码的普通短信登录。运营商要求额外安全验证时，程序显示错误码，不自动绕过。第三方服务及协议更新可能需要适配。部分问题只返回内部查询进度而没有答案时，会明确提示没有收到结果。

## 文件与接口

灵犀定时发送位于 `/lingxi/tasks`，对话侧栏和功能中心均有入口。选择共享账号、填写内容与北京时间即可预约；默认连续发送 3 次、间隔 1 秒，次数可设 1～20 次，间隔可设 0.2～3600 秒，一轮总时长不超过 1 小时。支持多账号预约、每周同一天重复、调整、停止、删除和查看每次回复。

新建任务的账号区域支持全选／取消全选，只选择可用账号。任务列表可按账号、号码尾号、发送内容和具体状态筛选，再全选当前结果，批量停止或删除。切换筛选会清空选择，不会操作隐藏的结果；执行中的任务需先「停止所选」，正在接收的回复会保留，结束后再「删除所选」。已完成、部分完成等已结束记录可直接批量删除。删除前会列出所选任务并确认，待执行的预约删除后不再发送。整批删除使用同一数据库事务，有任务已开始或写入失败时均不删除。勾选项全部为待执行任务时，还可批量调整内容、时间、次数、间隔或重复方式；只有勾选的字段会改变。批量调整保留原任务 ID、账号绑定和执行记录；若有任务已开始执行或某项参数无效，整批不保存。

每次请求按预约时间加间隔进入发送队列，使用独立对话接收回复，不等待上一条回复完成。提前 30 秒准备账号，发出前读取共享账号池最新凭据；准备超时或错过时间时不补发。任务与定制内容、回复加密保存在同一 SQLite 数据库的 `lingxi_tasks` 表中。关闭网页后仍会执行，电脑和本地服务需保持运行。停止会取消尚未发出的消息，已发出的请求继续保存回复。重启不会重放已开始或可能已经发出的消息；每周任务在中断后转到下一周。退出账号会停止该账号的定时发送。

任务页右上角“发送设置”可修改全局并发上限，默认 256，可设为 1～1024。超过上限的请求进入先进先出队列，等待空闲名额后发送，不再因并发已满而漏发；排队期间实际发送时间可晚于预约时间。执行记录显示入队时间、实际发起时间和排队时长，列表底部显示当前并发设置、进行中请求数与排队数。设置保存到同一 SQLite 的 `lingxi_settings` 表，立即生效并在重启后恢复；降低上限不会中断正在接收的回复，停止任务会移除其排队请求。服务中断后不自动重放未确定是否已发出的旧请求。

列表原“本轮收到 N 次回复”的位置展示最后一条有效回复摘要，按成功回复完成时间选择，跳过失败、排队与未完成内容；当前轮次尚无有效回复时沿用保留的往期回复。回复次数仍显示在任务信息中，完整内容通过“查看回复”读取。

任务列表使用表格展示账号、状态、内容、北京时间预约、发送次数与间隔、执行进度、最后有效回复和操作。所有行随页面铺开，纵向滚动整个页面，窄屏保留表格横向滚动；勾选、筛选和批量调整继续可用。

定时发送接口：`GET /api/lingxi/tasks`、`GET /api/lingxi/tasks/<id>`、`POST /api/lingxi/tasks/save`、`POST /api/lingxi/tasks/stop`、`POST /api/lingxi/tasks/delete`。保存参数为 `login_ids`、`content`、`run_at`（北京时间或带时区 ISO 时间）、`repeat_count`（默认 3）、`interval`（秒，默认 1）、`weekly`（默认 false）；编辑另传任务 `id`。列表不传输完整回复，详情按需读取。

批量调整接口为 `POST /api/lingxi/tasks/adjust`，传入 `ids`（任务 ID 列表）和 `changes`（只包含要修改的 `content`、`run_at`、`repeat_count`、`interval`、`weekly` 字段）。批量保存使用同一数据库事务，不创建新任务。

批量删除接口为 `POST /api/lingxi/tasks/delete-batch`，传入 `ids`（任务 ID 列表）；先校验全部任务已退出执行状态，再一次性删除数据库和内存中的相同任务，返回实际删除的 `ids`。

批量停止接口为 `POST /api/lingxi/tasks/stop-batch`，传入 `ids`；取消尚未发出的请求并保留正在接收的回复，不改写已结束任务的状态，返回实际停止的 `ids`。

并发设置接口：`GET /api/lingxi/settings` 返回 `concurrency`、`running`、`queued`；`POST /api/lingxi/settings` 接收 `{"concurrency":256}`。任务列表响应也包含运行时设置快照。

- `app.py`：本机 HTTP API、浏览器会话隔离、凭据内存管理。
- `app_login.py`：纯 Python 登录加密、短信登录、主会话维护及凭据续期协议。
- `app_login_public_key.json`：APK 中的公开 RSA 公钥，不含用户凭据。
- `lingxi_client.py`：Cookie 换取灵犀凭据、验证、流式文字收发。
- `templates/`、`static/`：简单前端。
- `static/workspace.js`、`static/workspace.css`：统一导航层级、页面样式和首页概览。
- `android_bridge.py`、`tools/`：此前分析工具，正常程序不加载或调用。

| 接口 | 用途 |
| --- | --- |
| POST /api/login/sms | 向输入的 phone 发送验证码 |
| POST /api/login | 用 phone、code 登录并自动连接灵犀 |

程序只监听本机。端口可通过 LINGXI_PORT 覆盖，默认 5500。

## Android 独立版

下载发布页中的 `LingxiWorkspace-1.1.0-Android-arm64.apk`，适用 Android 7.0 及以上的 64 位 ARM 手机。安装后直接打开，无需电脑、Python 或 USB。界面通过系统 WebView 展示，Python 服务、SQLite、账号登录和定时任务均在手机内运行；应用仅监听手机回环地址，并由每次启动的随机会话限制访问。

登录凭据使用 Android Keystore 加密，Windows 仍使用 DPAPI。两端各自保存数据，不会把发布者账号打包，也不自动复制电脑的登录态。同一手机号遵循运营商的单点登录规则。付款始终由用户在官方 APP 手动完成。

应用运行时显示后台通知，可从通知或应用菜单停止。定时任务需要联网和后台服务运行；请按手机系统设置允许后台运行。系统强制停止、关机或休眠限制可能导致错过时间；启动后仍会按已有规则补查签到。安卓版本次只完成构建、签名检查和安装，手机功能实测由用户进行。
